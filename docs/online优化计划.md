# online 优化计划：补齐临床量的图、基线与 AUC 分离

> 2026-10-26 起草，同日按复查意见修订（第十节列出修订点）。
> 目标：主界面画出 TOI / ΔHbO / ΔHbR / ΔtHb / THI(ΔTHI) / ΔTOI / AUC；
> BL 基线可「自动 / 抓取 / 手填」；AUC 有自己的参考点和复位按钮；
> 时间窗可选；能打事件标记。ΔCyt 不做。MBLL 从 online 移除（第九节）。

---

## 一、已定的决策

| 项 | 决定 | 谁定 |
|---|---|---|
| AUC 警戒线 | 参考 TOI × (1 − 0.20)，即相对基线下 20% | 用户选「往下 20」；「%还是点」用户未答，按建议取相对（第二节） |
| BL 基线设置 | 「抓取当前」+ 可手填 TOI；浓度基线只能抓取 | 用户 |
| 自动基线 | 开机自动，等光强稳定；**5 分钟仍不稳则照设并标「未稳定」** | 用户定「等稳定」；超时行为按复查建议 |
| 布局 | 主页放临床量，μa 移到「调试」页 | 用户 |
| MBLL | 从 online 移除，模块与命令行保留 | 用户提出；「以后做不做任务态」未答 |
| 状态机位置 | **放逻辑层 `srs.py`**，界面只调方法、读状态 | 复查修订 |

## 二、AUC 警戒线口径：相对 20%

| | 基线 70 时的警戒线 | 基线 88 时 |
|---|---|---|
| 减 20 个点 | 50 | 68 |
| **乘 0.8（采用）** | **56** | **70.4** |

依据：文献的相对口径同时用了「低于基线 10% / 20% / **50%**」—— 50% 只能是相对值（文献）；
BRS-100 说明书 p31 称之为「监测数值与基线的**差值比率**」（说明书原文）。
常数 `AUC_REL_DROP = 0.20`，改口径只改一处。两种口径都远大于噪声（ΔTOI σ 0.07~2.42）。

## 三、现状 → 目标

| 量 | 现在 | 改后 |
|---|---|---|
| TOI | 曲线 | 曲线 + **BL 虚线** + **AUC 警戒线（点线）** |
| ΔHbO / ΔHbR / ΔtHb | 曲线 | 不变 |
| THI / ΔTHI | 读数行里一个数 | **ΔTHI 曲线**，读数显示 THI |
| ΔTOI | 算了没画 | **曲线**，与 ΔTHI 同一格；读数同时给点数与 % |
| AUC | 读数行里一个数 | **曲线** + 读数「x %·min，低于警戒线 mm:ss」 |
| μa | 主页第 2 行 | 移到「调试」页 |
| MBLL ΔHbO/ΔHbR | 主页第 3 行 | **移除**（第九节） |
| 时间窗 | 固定 60 s（`SPAN_S`） | **可选 1 分钟 / 10 分钟 / 1 小时 / 全程** |
| 事件标记 | 无 | **按钮 + 文字**，图上画竖线，写入归档旁的 `.events.csv` |

## 四、设计

### 4.1 逻辑层 —— 全部放 `fnirs_pipeline/srs.py`（纯 numpy，可移植安卓）

界面层只做显示和按钮。**判断逻辑、状态机一律在这一层**，安卓端拿到的就是同一份行为，
自检和归档回放也能直接测它。所有类都是实例状态、无模块级全局 —— 双通道设备每通道一个实例。

**① `AucAccumulator` 改造**

| | 现在 | 改后 |
|---|---|---|
| 参考点 | 无，喂 ΔTOI（相对 BL） | 自带 `ref_toi`，`reset(ref_toi)` 时设定 |
| 累加条件 | `d_toi < 0` | `toi < ref_toi × (1 − AUC_REL_DROP)` |
| 累加量 | `−d_toi · dt` | `(警戒线 − toi) · dt` |
| 输入 | `push(t, d_toi)` | `push(t, toi)`（绝对 TOI） |
| 输出 | `value`（%·s）、`seconds` | 同上 + `value_min`、`threshold` |

自带参考点 → BL 怎么改都动不到 AUC（MOC400 的设计）。
显示 %·min：相对口径的文献截断值是 min%（如「>150 min%，基线下 20%」，PMC8437017）。

**② `Baseline` 加三个带默认值的字段**：`source`（auto / captured / manual）、
`low_signal`、`unstable`。手填 = `replace(bl, toi=x, source="manual")`，浓度字段不动。
`Derived` 加 `d_toi_rel`（ΔTOI 占基线 %）。

**③ `baseline_reject_reason(res)`** —— 攒基线时哪些点不收：

| flag | 处理 | 理由 |
|---|---|---|
| TOI_raw 越界 / HbO·HbR 负值 / μeff 非正 | **挡** | 物理上不可能 |
| 最远探测器计数不足 | **收，基线标 `low_signal`** | 前额 670/4cm 可能一直低于 2000（未测），挡了就永远设不上 |
| tHb 越界 | **收** | 体模上恒触发（111030 tHb 12.31 µM），挡了体模永远设不上 |

**④ `SettleGate`** —— 两条都满足才算稳：
光强最高那一路（当前为 770/3cm）过去 60 s 内 ln(I) 线性拟合的总变化 < **2%**（贴稳了）；
**且** 过去 60 s TOI 线性总变化 < **5 个点**（生理平稳）。

第二条是实施时用真实归档截图发现后加的（第十一节）：光强稳 ≠ TOI 稳。

| 记录 | 类型 | 770/3cm 60s 变化 p50 | p90 | 第一个可判值 |
|---|---|---|---|---|
| 111030 | A2 体模静止 | 0.1% | 0.2% | 0.2% |
| 141147 | 体模低光 | 0.2% | 0.4% | 0.0% |
| 164708 | 体模低光 | 0.3% | 0.8% | 1.4% |
| **131237** | **在体刚贴上** | **10.0%** | 11.1% | **6.2%** |
| 150943 | 手臂勒紧 | 8.1% | 13.5% | 1.1% |
| 134037 | 在体 | 6.8% | 99.4% | 3.4% |
| 103952 | 在体 | 2.0% | 48.7% | 3.2% |

不用「四路取最大」或「四路共模」：两者都混入低光 670/4cm 自身噪声（低光体模 p90 达 3~20%）。
⚠️ 8 份记录全是手臂和体模，**前额未测**。

**⑤ `BaselineManager`** —— 基线与 AUC 的全部状态

```
reset()（连接 / 清屏）
   ▼
等待稳定 ──(5 分钟未稳)──► 采集中（auto，标 unstable，不再因不稳作废）
   │ SettleGate 通过
   ▼
采集中 n/20 ──(auto 且期间不稳)──► 等待稳定（等待计时不清零）
   │ 攒满（只收 baseline_reject_reason 为空的点）
   ▼
已设 ── 首次已设且 AUC 无参考点 → AUC 继承 BL 的 TOI
   │
   ├ capture()          → BL 立即作废 → 采集中（captured，不等稳定）→ 已设
   ├ set_manual_toi(x)  → 只改 BL 的 TOI，source=manual；AUC 不动
   └ reset_auc()        → AUC 清零，参考点 = 当前 BL 的 TOI；BL 不动
```

`push(t, res, intensities) -> Derived | None`。**AUC 在任何阶段都照常累计**（只认自己的参考点），
所以重新抓 BL 的那 30 秒里 AUC 不断档。`t` 用**数据时刻**（帧的 `t_host`），不用反演那一刻的
`perf_counter` —— 前者才是光被测到的时刻，也使回放与自检可复现。

## 五、不做的，及原因

| 项 | 原因 |
|---|---|
| ΔCyt | 两波长无解；四波长时在体 ΔHbO σ 2.73 µM 是 oxCCO 信号 0.24 µM 的 11 倍 |
| 绝对浓度 CHbO2 / CHb / CtHb（BRS-100 p31 有） | 本机绝对 tHb 不可信：体模 111030 读 12.31 µM、141147 读 46.47 µM；μs′ 为假设值、k/b 未标 |
| 报警（上下限、基线差值） | 竞品核心功能，但属于安卓端产品层；解码器只需提供基线与差值 |
| 带 flag 的点仍进 TOI 曲线 | 「不悄悄丢数据」的设计选择 |
| tHb 判据在体模上恒报警 | 放宽下限还是加体模模式，另议 |

## 九、MBLL 从 online 移除

**① 看不见持续变化。** 带通 0.01~0.05 Hz。合成一次持续 4 分钟的 ΔHbO −10 / ΔHbR +5 µM
（无噪声，用解码器自己的正演公式），平台期 MBLL 解出均值 **+0.09**，真值 −10.00 —— 只在起止各冒一下。
**② 要等 300 s 才出数**，SRS 派生量开机即有。**③ 依赖 scipy 零相位滤波，进不了安卓。**
**④ BRS-100 整机不含 MBLL。**

保留 `mbll_decoder/` 全部代码、`python -m mbll_decoder.run <归档>`、t15 与 t16 中 `LiveMbll` 的检查。
失去的是快变化上低 12 倍的噪声底（0.124 vs 1.486 µM）—— 只对任务态有用。

## 十、修订记录（同日复查）

| 修订 | 原因 |
|---|---|
| 状态机从界面层移到逻辑层 `BaselineManager` | 原计划自相矛盾（4.1 说逻辑不进 online，4.2 却把状态机放 online）；安卓需同一份行为 |
| 加时间窗选择 | 60 s 窗看不见基线漂移与 AUC；BRS-100 窗口可设、可回看整段（p35）；数据本就保留约 8.5 h |
| 加事件标记 | BRS-100 有（p35）；动脉阻断实验要标袖带起止 |
| 「计数不足」不挡基线，改标 `low_signal` | 前额可能一直低于 2000 counts，挡了就永远设不上 |
| 超时照设并标「未稳定」 | 竞品开机总会自动设基线；在体可能很少满足 2%，否则自动基线形同虚设 |
| ΔTOI 同时显示 % | 与相对口径的 AUC 警戒线、BRS-100「差值比率」一致 |
| 不显示绝对浓度，写明理由 | 竞品显示，本机不可信 |

## 十一、实施结果（2026-10-26）

自检 **191/191**（158 → 删 t16 中挂界面的 9 项、加 t17/t18/t19 共 42 项）。

**归档回放（逻辑层，不经界面）：**

| 记录 | 类型 | 首次稳定 | 基线设定 | 来源 | 标记 | BL TOI | AUC %·min |
|---|---|---|---|---|---|---|---|
| 111030 | A2 体模 | 92 s | 120 s | auto | | 83.9 | 0.00 |
| 141147 | 体模低光 | 91 s | 119 s | auto | | 79.8 | 0.00 |
| 164708 | 体模低光 | 121 s | 192 s | auto | | 81.7 | 0.00 |
| 131237 | 在体刚贴上 | — | — | 等待中 | | — | 0.00 |
| 103952 | 在体 | 134 s | 324 s | auto | | 77.3 | 0.00 |
| 134407 | 阻断+脱开 | 97 s | 381 s | auto | 未稳定 | 80.9 | 18.13 |

体模上 AUC 恒为 0（旧语义下 141147 / 164708 为 662 / 1013 %·s）。
134407 的 18.13 来自探头脱开的伪迹（TOI 冲到 300），不是去饱和。

**实施中发现并修正**：初版只有光强判据。用 103952 截图时看到基线设在 TOI 爬升途中
（t=157 s，65.0，此后 TOI 稳在 75 上下，整段 ΔTOI 带 +10 偏移）。原因是 TOI 由两波长**比值**
决定，单一路光强平着时 TOI 照样能大变。加 TOI 判据后基线设在 t=324 s 的平台上（77.3）。
