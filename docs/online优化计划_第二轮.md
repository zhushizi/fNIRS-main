# online 优化计划（第二轮）：出值提速 + 补 THI 绝对指数

> 2026-10-26 第二轮。第一轮见 `docs/online优化计划.md`（已实施，191/191）。
> 本轮三件事：**A** 稳定判据从「闸门」改「指示灯」；~~**D** 窗口没满也出 TOI~~（**实施中实测否决**，见 §九）；
> **T** 补上不依赖基线的 THI 绝对指数。

## 一、为什么要改

第一轮把自动基线设计成「等信号稳定才设」。实测下来代价远大于收益。

**时间拆解**（111030，最顺利的一份）：

```
30.7 s   第一帧 → 第一个 TOI 点（攒满 AVG=20 个周期）
60.9 s   第一个 TOI → 判据可判（SettleGate 窗口 60 s）
28.9 s   判据通过 → 再攒 20 点出基线
───────
120.5 s  ← 第一个相对量
```

在体更久：103952 要 324 s，134407 要 381 s，**而 131237 / 134037 / 150943 三份全程没设上基线**。

**等待买到的精度**（同一评估窗上的 |ΔTOI| 中位，越小越好）：

| 记录 | 类型 | 现状（等稳定） | 立即设（60 s） |
|---|---|---|---|
| 111030 | A2 体模 | 0.1 | 0.1 |
| 141147 | 体模低光 | 1.5 | **1.1** |
| 164708 | 体模低光 | **1.2** | 1.6 |
| 131237 | 在体刚贴 | **未设** | 0.6 |
| 134037 | 在体 | **未设** | 0.8 |
| 150943 | 手臂勒紧 | **未设** | 2.3 |
| 103952 | 在体 | 11.7 | 12.2 |
| 134407 | 阻断脱开 | 4.8 | 5.2 |

**差异全部 ≤ 0.5 点，而 ΔTOI 噪声底是 1.2~1.9。** 等 2~6 分钟买到的东西在噪声底以下，
代价是 3/8 的记录完全没有相对量。依据：实测。

> ⚠️ 这是推翻第一轮我自己的设计。当时拿 131237（刚贴上、光强涨 46%）一个例子就定了
> 「必须等稳定」，**没有量「等待买到多少精度」**。量了之后结论反了。

竞品也不等：BRS-100 说明书 p34「开始监测后，系统会**自动计算基线**」，无等待条件，另给校准按钮。

## 二、A：判据从「闸门」改「指示灯」

### 改什么

`BaselineManager` **去掉 WAITING 阶段**。连接 / 清屏后直接进 COLLECTING，攒够 N 点就设基线。

`SettleGate` 照常跑，但只在**定基线那一刻**被读一次，结果写进 `Baseline.unstable`：

| 定基线时 | 标记 | 界面 |
|---|---|---|
| 判据通过 | — | 已设 TOI 77.3（自动） |
| 判据不通过 / 还没攒满 60 s 窗 | `unstable=True` | 已设 TOI 65.0（自动）**⚠ 未稳定** |

**新增一条提示**（不自动动基线）：基线标了 `unstable`、而判据**后来**通过了 →
状态行提示「信号已稳定，建议点『抓取当前』重设基线」。由操作者决定，不自作主张。

### 为什么不自动精化

试过。临时基线 + 稳定后自动精化一次，实测：

| 记录 | 临时基线 | 自动精化 | 改了多少 |
|---|---|---|---|
| 111030 | 60 s 84.0 | 120 s 83.9 | −0.1 |
| 141147 | 59 s 81.1 | 119 s 79.8 | −1.3 |
| 164708 | 58 s 83.4 | 192 s 81.7 | −1.7 |
| 103952 | 59 s 76.8 | 324 s 77.3 | +0.4 |
| 其余 4 份 | — | **未触发** | — |

精度对比：2 份变好、1 份变坏、1 份持平，差异 ≤ 0.5 点。
**8 份里只有一半触发，收益在噪声底以下，而让监护仪的参考点自己移动是个坏性质。** 否决。

### 常量去留

| | 处置 |
|---|---|
| `SETTLE_WIN_S` / `SETTLE_MAX_REL` / `SETTLE_MAX_TOI_PTS` | 保留，判据仍在跑 |
| `SETTLE_TIMEOUT_S` | **删除** —— 不再有「等到超时」这回事 |

## 三、~~D：窗口没满也出 TOI~~ —— 实测否决，见 §九

### 改什么

`_push_net` 的出点条件从「每一路都攒够 `need` 个」改成「每一路至少 1 个」，
`last_n` 如实报当前 n（界面已有「n 周期平均」）。

实测首个 TOI 点：**30.7 s → 1.8 s**。

### 为什么基线不能用部分窗的点

**会错得很离谱。** 实测用部分窗的点算基线，与满窗基线相差：

| 记录 | 基线差 |
|---|---|
| 164708 | −0.02 |
| 111030 | −0.24 |
| 134037 | −0.32 |
| 150943 | +1.39 |
| 131237 | +1.94 |
| 134407 | +2.08 |
| 141147 | −4.56 |
| **103952** | **−23.48** |

根因在 `robust.aggregate` 的 `MIN_N = 4`：**窗里不足 4 个样本时退回算术均值、不剔尖峰**。
而 103952 的尖峰剔除率是 16%，开头那几点把尖峰直接吃进基线。

**所以 online 只在 `n >= need` 时才调 `bl.push()`**，部分窗的点只进 TOI 曲线和读数。
判据同理（它本来就要 60 s 窗，不差这 30 s）。

基线时刻因此仍是 **~59 s**，与「立即设」一致。

### 代价

开头那几点噪声大。111030（真值恒定）实测：

| | 前 20 点 TOI std |
|---|---|
| 部分窗 | 0.264 |
| 满窗 | 0.061 |

差 4.3 倍，但绝对值 < 0.3 点，屏幕上看不出来。n 会写在读数行里（「3 周期平均」），不会假装已经稳了。

⚠️ **副作用**：质量层的「尖峰剔除率」在 n < 4 时恒为 0%（`aggregate` 没剔）。
开头几秒这个指标偏乐观。不改它 —— 但在读数行的 n 上能看出来当前是不是部分窗。

## 四、T：补 THI 绝对指数

### 它是什么

SRS 解 μa 要除以**假设的** μs′：`μa = μeff²/(3·μs′)`。若真实 μs′ 是假设的 k 倍：

| | k 的影响 |
|---|---|
| TOI = HbO/(HbO+HbR) | 分子分母同时缩放，**约掉** → 绝对值 |
| tHb = HbO+HbR | 缩放**留着** → 只能叫「指数」 |

这正是 NIRO 报 TOI（%）却只报 nTHI（指数）的原因，也是 `docs/对标分析.md` §1.3 写的
`THI = k·(C_HbO+C_HbR)`。

**这个量我们一直在算** —— `SrsResult.thb_uM`，每点都有，**不需要基线**。只是没显示。

### 现状盘点

| | 现状 | 本轮 |
|---|---|---|
| THI 绝对指数 = k·tHb | 算了没显示 | **显示：读数 + 曲线** |
| THI 归一化 = 100 × tHb/基线tHb | 读数行有（`THI 138.8%`） | 保留，并排显示 |
| ΔTHI = THI − 100 | 有曲线 | 保留 |

### ⚠️ 一处没确认的口径

MOC400 界面显示 **THI 1.38**。两种可能：

- **归一化**（NIRO 的 nTHI 口径，起点恒为 1.00）→ 1.38 = 比开机时高 38%
  **我们的 `138.8%` 换个写法就是 1.388，即同一个量**
- **原始指数** k·tHb → 但我们实测在体 tHb 是 33~54 µM 量级，不会显示成 1.38

**倾向前者**，依据：数值量级 + NIRO 约定。⚠️ **这是推测**，不是来自 MOC400 文档 ——
项目里关于 MOC400 的全部材料只有一张官网配图（`对标分析.md:464`）。

**因此本轮两个都显示、都标清口径**，等拿到 MOC400 开机那一刻的截图（THI 若显示 1.00 即归一化）
再决定主显示哪个。两个都在界面上，不会因为猜错而要返工。

### 单位怎么写

绝对指数写成 **µM 并注明是指数**：`THI 54.3 µM（指数，μs′ 为假设值）`。

不写成无量纲数的理由：我们算出来的就是 µM，硬除一个数变成「1.38」需要先定一个参考，
而那个参考正是没确认的东西。**宁可写得啰嗦，不要写得像已经对齐了竞品。**

## 五、界面布局

```
┌ 主页 ┬ 调试 ┐
│ TOI ───────  BL - - - -  AUC 警戒线 ·········│   (%)
│ THI（绝对指数，不依赖基线）                    │   (µM)   ← 新增
│ ΔHbO  ΔHbR  ΔtHb                            │   (µM)
│ ΔTHI  ΔTOI                                  │   (%)
│ AUC                                         │   (%·min)
└──────────────────────────────────────────────┘
调试页：μa
```

THI 那一格放在 TOI 下面：两者都是**绝对量、不需要基线**，开机就有数；
下面三格都要基线。这样「上面两格立刻有、下面三格等 59 s」在视觉上就分开了。

### 读数行重排

现在七项挤一行，你找不到 THI 正是因为这个。按「要不要基线」分两行：

```
绝对量　TOI 77.3　THI 54.3 µM（指数）
相对量　ΔHbO +20.96　ΔHbR −5.57　ΔtHb +15.39 µM　THI 138.8%　ΔTOI +16.5（+21.3%）　AUC 0.0 %·min（低于警戒线 00:00）
```

没基线时第二行显示「相对量　等基线（采集中 12/20）」。

| 141147 | 体模低光 | 59 s | 81.1 | 0.00 |

### ✗ 否决 D：窗口没满也出 TOI

计划里写「代价：前 20 点 std 0.264 vs 满窗 0.061，差 4.3 倍但绝对值 <0.3 点，屏幕上看不出来」。
**这个数只在 111030（最干净的体模）上成立，不能推广。** 实施后在 8 份上实测
「用 n 个周期算的 TOI」减「同一时刻用 20 周期算的」：

| 记录 | n=1 中位/p90 | n=10 中位/p90 |
|---|---|---|
| 111030 A2 体模 | 0.2 / 0.4 | 0.0 / 0.1 |
| 141147 体模低光 | 7.2 / **20.1** | 1.5 / 4.1 |
| 164708 体模低光 | 6.1 / **19.2** | 1.8 / 5.2 |
| 103952 在体 | 7.2 / **23.1** | 2.7 / 7.7 |
| 134407 阻断脱开 | 3.7 / 11.8 | 1.6 / 7.9 |

103952 开头几点读 **42，真值 74**。根因：**TOI 是光强的非线性函数**（μa ∝ μeff²），
单周期噪声不是散开而是**有偏**，所以不像均值那样「多等几个点就收敛」。
主读数上放一个错 32 点的数不可接受。

**改为**：窗口没攒满时在 TOI 图里画进度（`n / 20 周期，还差 x s`），不出数。
想更快就把工具栏的「平均」调小 —— 这是本来就有的、操作者可控的权衡。

> 教训：**把只在最干净那份数据上量到的代价，当成了普遍代价。**
> 和第一轮「拿 131237 一个例子就定判据」是同一个错误 —— 样本不够就下结论。
> 这次是写进计划、改完代码、截图时才发现。

### unstable 的语义在实施中修正

初版把「判据窗还没攒满」也算成不稳。结果 8 份归档**全部**标红 ——
基线在 ~59 s 设上，而判据窗是 60 s，此时必然 `ready=False`。
这和 tHb 判据在体模上 237/237 报警是同一个毛病：**恒亮的告警灯等于没有灯**。

改为：`unstable` 只在「判过且没通过」时为真；当前信号稳不稳由状态栏**实时**显示
（`信号：稳定` / `信号：在变（60s 内光强 95.3%、TOI 1.9 点）` / `信号：攒满 60s 才能判`）。
判据是指示灯 —— 那就让它当一盏**实时**的灯，而不是冻在基线上的一个标记。

### THI 口径已确认（按用户提供的 MOC400 界面照片）

照片读数：`ΔCyt 7.73`、`ΔO₂Hb 7.23`、`THI 2.83`、`ΔHHb −4.17`、`ΔTHI 1.83`、`3.06`。

两条恒等式都严丝合缝：

| | 算式 | 结论 |
|---|---|---|
| ΔO₂Hb + ΔHHb = ΔtHb | 7.23 + (−4.17) = **3.06** | tHb 是 HbO 与 HbR 的和，不是独立量 |
| THI − ΔTHI = **1.00** | 2.83 − 1.83 = 1.00 | **THI 归一化，基线恒为 1.00**，ΔTHI = THI − 1 |

→ 与 NIRO 的 nTHI 同一约定。之前只能从「1.38 的量级」推测，现在由两个读数算出，**确定**。

**据此改动**：
- `Derived.thi` 从「% 基线（基线=100）」改为**比值**（基线=1.00），`d_thi = thi − 1`
- 读数行按 MOC400 写法：`THI 1.37　ΔTHI +0.37`
- **删掉本轮加的「THI 绝对指数（µM）」那一格** —— MOC400 屏上没有这个量，对标以它为准。
  量仍在算（`SrsResult.thb_uM`），只是不显示。主页回到四格。
- ΔTHI 画图时 ×100 换成百分比，才与同格的 ΔTOI 量级可比；读数仍用比值。

**一处对不上，留档**：若 THI 与 ΔtHb 出自同一条链，基线 tHb = 3.06 ÷ 1.83 = **1.67**，
而组织 tHb 应是 40~80 µM 量级。可能解释是 **THI 走 SRS、Δ 量走 MBLL，两条链标度本就不一致**
（NIRO 即如此，`对标分析.md:68`）。依据：推测。
提醒：**我们的 THI 与 ΔtHb 同出一条 SRS 链，严格自洽；竞品未必。对标数值时别假设对方内部一致。**

### THI 那一格：加 → 删 → 恢复（判据随证据变）

| 看到的证据 | 判断 | 动作 |
|---|---|---|
| 竞品照片①：`THI 2.83`、`ΔTHI 1.83`，差恰为 1.00 | THI 是归一化值（基线=1） | 删掉绝对指数那一格 |
| 竞品照片②：多出 `BL 82`、`rSO₂ 81` | **病人是稳的**，而 THI 2.83 若是「当前 tHb ÷ 基线 tHb」就意味着总血红蛋白涨到近 3 倍 —— 不可能 | **恢复**那一格 |

**最终：两种读法都留在界面上**，免得再猜错返工：

- **指数**（µM，不依赖基线）：主页第 2 格曲线 + 读数行第一行 `THI 55.0 µM（指数）`
- **比值**（基线 = 1.00，对齐 MOC400 写法）：读数行第二行 `THI 1.37　ΔTHI +0.37`

⚠️ 竞品那两条恒等式（ΔO₂Hb+ΔHHb=ΔtHb、THI−ΔTHI=1.00）各自精确成立，
但组合起来推出基线 tHb = 3.06/1.83 = 1.67，远在生理 20~120 µM 之外。
**说明其 THI 与 Δ 量不同链/不同标度**，两条读法并存是目前最稳妥的处理。

### 读数改成带标签的格子

用户**两次**说找不到 THI。第一次我把一行拆成「绝对量 / 相对量」两行，
但相对量那行仍是七项挤在一起、THI 排第 4 —— 没解决问题。

改为 MOC400 那样**一格一个量、标题常驻**，八格两行：

```
THI 指数(µM)  ΔHbO(µM)   ΔHbR(µM)   ΔtHb(µM)
    55.0       +20.72     −5.82      +14.90
THI 比值      ΔTHI       ΔTOI(%O₂)  AUC(%·min)
    1.37       +0.37     +16.9(+22.0%)  5.7(01:02)
```

**标题自带限定词**（「THI 指数」/「THI 比值」）—— 「THI」单独出现指不清是哪个，
这正是前面一连串误判的源头。文字行只留状态与告警。
