# 第一部分　通用约定（可搬走）

## 读的人不跑任何命令，写的人不新增入口

**日志自带实测快照** —— 每天的 md 里有一段测试/校验工具的**原样输出**，
不是手敲的数字。你只读文件。

数字必须是程序打印的。手敲的数字又变回「作者的说法」，而这个文件
存在的意义正是让你能查他。

但**不要为此新建脚本**。用项目**本来就有的**那个命令（这里是
`python -m srs_cal.selftest`），把尾部摘要贴进去就够了。

> 这条是踩出来的：我一度新建了 `check.py` 把自检和数据流追踪合成一条命令，
> 用户的反馈是「还要再跑一个代码才能看到，太麻烦」「check.py 就不要了」。
> **「合并成一个入口」仍然是 +1 个入口。** 他要的是不增加。

⚠️ **快照是当天的，不跟着代码自动更新。** 每天重跑重贴；看旧日志时要意识到
那是当时的状态。

⚠️ **别用文本匹配去数工具已经数好的东西。** `check.py` 用 `grep` 数出 144 条，
而自检自己报 143 —— 多出的一行根本不是检查项。直接用权威输出。

## 变更记录：每天一个 `YYYY-MM-DD.md`

当天没改动就不建文件 —— 空文件比没文件更误导。

它记的是**为什么这么改**和**试过什么没成**，不是 `git diff` 的复述。
改了哪几行 git 比这里清楚，两者不互相替代。

### 一条长什么样

```markdown
### 14:32　把 DEFAULT_AVG 从 10 改成 20

- **角色**：实现
- **改了什么**：`software/srs_cal/online.py:94`
- **为什么**：N=10 时 std 3.06，N=20 降到 1.59，只付 2 倍滞后；
  20→40 只再降 1.3 倍却又付 2 倍滞后，拐点在 20
- **依据**：实测（10 分钟体模静置，424 周期重放）
- **怎么确信的**：同一份数据重放四种配置对比，不是单跑一次看着像
- **验证**：自检 t14；`docs/验证图/…png`
```

### 「依据」必须填，只能四选一

| 值 | 含义 |
|---|---|
| **实测** | 本项目真实数据跑出来的，能复现 |
| **厂家确认 / 上游确认** | 对方明确答复过（写日期） |
| **文献** | 有出处，写出处 |
| **推测** | 反推、类比、还没验证的 |

**这是整个文件最重要的一栏。** 标成「推测」的东西，后来的人就不会当事实用。

### 「怎么确信的」—— 写推理路径，不写结论

结论会过期，推理方式不会。

> 例：怎么知道 ADC 是有符号数？—— 实测序列 `+1,066,481 → −157,062 →
> −2,032,556` 是**连续过零**的，只有有符号解读才连续，无符号下会从
> 106 万跳到 42.9 亿。

这个判断方式能迁移到别的问题上，「ADC 是有符号的」这个结论不能。

### 「验证」填不出来就填「无」

没验证的变更要显形，不要含糊过去。

## 每天的文件结构

```markdown
# YYYY-MM-DD
> 一句话：今天干成了什么

## 状态          自检 N/N | 改动 +X/−Y | 新建 Z 行 | 是否提交
## 今天的实测快照  ← 已有测试命令的原样输出。读的人不用跑任何命令
## 变更          按 HH:MM 排
## 推翻 / 否决 / 作废     ← 没改代码但结论变了的。**这是本文件相对 git 的全部价值**
## 踩的坑        我犯的错 + 怎么发现的
## 悬而未决      没解决、等决策或等数据的
```

## 什么算一条

**记**：改变行为、结论或接口的变动。
**不记**：重命名、格式化、注释笔误、纯重构 —— 看 `git diff`。

**没有代码变动但必须记的两类：**

1. **结论被推翻** —— 代码一行没动，但依据变了
2. **方案被否决** —— 没改代码，但以后别再试了，写明为什么不行

## 我这边的习惯（不需要你同意，我照做）

**每个结论都带适用范围和证据强度，不等你来查。**

反例：我说过「稳健聚合降噪」，但那是**在体数据**的结论 ——
体模上实测反而略亏（2.23 vs 2.19），因为剔除率只有 0.49%，等于在扔好点。
当时如果直接写明适用范围，就不用你回头去查。

# 第二部分　本项目特定

- 自检：`cd software && python -m srs_cal.selftest`
- 日志：`.claude/变更记录/YYYY-MM-DD.md`
- 技术论证：`docs/双解码器架构.md`（§七 是变更摘要，细节在本目录）
- 验证图与生成脚本：`docs/验证图/`
- 代码：`software/`

## 已知的两个位置问题

1. **`.claude/` 对外部人不可见。** 同事或审评的人翻仓库不会想到来这里 ——
   这个目录名看起来就是工具配置。要给外部看的话，整个目录移到
   `docs/工作日志/`，改路径即可，内容不用动。
2. **`.claude/settings.local.json` 是本机配置不该提交。**
   已在 `.gitignore` 里单独排除，本目录可正常提交。
